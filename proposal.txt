Proposed Offline AI-Assisted Finish Line Timing and Bib Logging System
Executive Summary
We propose an offline, AI-assisted finish line monitoring system that uses a camera and laptop to detect runners as they cross the finish line, attempt to read their bib numbers, record a finish timestamp, and save the results directly into an Excel spreadsheet in real time. The goal of this system is to reduce manual timing workload, lessen encoding delays, improve race-day organization, and provide an engaging live visual experience for runners and spectators. The system is designed for efficient event operations, while still allowing manual verification and correction whenever a bib is unclear or missed.
System Overview
The proposed setup uses a DJI Osmo Pocket 3 mounted on a tripod near the finish line and connected to a laptop through USB-C in webcam mode. The laptop will serve as the main processing unit, where the video feed is analyzed in real time using object detection, tracking, and OCR tools. The same laptop can also output the annotated live view to a TV or LED display for audience visibility. Since the Osmo Pocket 3 can function as a webcam over USB-C but does not support direct real-time HDMI video output from its USB-C port, the laptop will be the central device for both processing and display.
How the System Works on Race Day
As runners approach the finish area, the camera captures a live video feed aimed toward the runners’ chest area, where bib numbers are expected to be visible. A virtual digital finish line will be defined within the video frame. When a runner crosses that line, the system will detect the runner, assign a tracked identity on-screen, and attempt to read the visible bib number from the relevant image region. At the moment of crossing, the system records a finish timestamp based on the laptop’s system clock. The detected bib number, timestamp, and status information are then saved into an Excel file automatically.
Because camera-based OCR is affected by visibility, motion blur, bib folds, body occlusion, and overlapping runners, the system should be presented as an AI-assisted logging solution rather than a fully autonomous official timing system. For this reason, the software will include confidence checks, duplicate prevention rules, and manual override tools to help ensure reliable final results.
Physical Setup and Equipment
The camera will be placed on a stable tripod near the finish line, angled slightly downward to maximize visibility of approaching runners’ bibs. The laptop operator will be seated nearby at the timing table, where the live feed, system alerts, and logging dashboard can be monitored continuously. A TV monitor or LED display may be connected from the laptop to show the annotated video feed, including tracking boxes and recent bib detections, creating a more interactive and modern finish line experience.
If the camera must be placed farther away from the laptop, the USB connection should be tested in advance using a proper data-capable cable or active extension solution. This part should not be assumed to work with any long passive Type-C extension without prior testing. For that reason, all cable lengths and display routing should be finalized during technical setup and rehearsal before race day.
Operator Dashboard
The operator dashboard is designed to be simple and practical during the event. On the left side of the screen, the operator will see the live camera feed with visual tracking overlays. On the right side, the system will display the most recent finish records, including bib number, timestamp, and detection status. A manual override input field will also be available so that if the system fails to read a bib clearly, the operator can type the correct bib number and immediately save or correct the entry. This ensures that the event team can continue operating smoothly even when difficult edge cases occur.
Data Output and Result Handling
All finish records will be written directly into an Excel spreadsheet stored on the laptop. The spreadsheet may include columns such as Finish Order, Bib Number, Finish Timestamp, Detection Confidence, and Review Status. This allows the event team to monitor incoming results live and also identify entries that may require manual review. The system can reduce post-race encoding time because results are logged continuously as runners finish, rather than being written entirely by hand after the event. However, final awarding results should still be reviewed by the organizers or timing team before official announcement.
Safety Nets and Fallback Procedures
To ensure dependable operation, the system will include multiple fallback measures. First, runners should be reminded before the race that bib numbers must remain clearly visible on the front of their chest when approaching the finish line. Second, if a bib is missed or partially covered, the operator can use the manual override field to enter the bib number immediately. Third, if a correction is needed after the crossing, the system should support manual editing of both bib number and timestamp under organizer supervision. Finally, the raw video feed should be retained whenever possible so the timing team can review unclear finish events if needed.
Requests from Event Organizers
To help the system perform reliably, we respectfully request the following support from the organizers:
Proper finish line lighting, especially if the event extends into late afternoon or early evening, so runners’ bibs remain readable as they approach the camera.
A TV monitor or LED wall connection from the laptop if the organizers would like a live public display of the finish line feed.
One table, two chairs, nearby power access, and extension wires for the operator station.
A short pre-race announcement reminding runners to keep their bib number clearly visible on their chest when finishing.
Enough setup time before the event for camera positioning, cable testing, finish-line calibration, lighting adjustment, and a short system dry run.
Recommended Organizer-Facing Clarification
This system is best described as an offline, AI-assisted finish line logging tool intended to support fun run operations, improve live monitoring, and speed up result preparation. It is designed to reduce manual work and improve accuracy, but like any camera-based system, it may still require operator intervention in cases involving unclear bibs, overlapping runners, or unusual finish situations. Because of this, the system should be used with a verification workflow before final official results are announced.
Closing Statement
With proper finish line placement, lighting, testing, and operator support, this proposed system can provide a practical and modern solution for fun run finish monitoring. It combines offline video capture, real-time bib recognition attempts, automated Excel logging, and manual safety controls into one event-ready workflow. Beyond improving race operations, it also offers a visually engaging and innovative experience for participants and spectators, while keeping the process grounded, reviewable, and manageable for organizers
